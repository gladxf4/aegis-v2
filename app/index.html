    Protocol

    What the circuit proves

    The relation is small enough to check by reading the circuit. It is not a claim about real government credentials.

    Relation

    public   ref_date, app_id, nonce, issuer_key_hash
private  dob, credential_uid,
         issuer_ax, issuer_ay,
         signature_r8x, signature_r8y, signature_s

prove    EdDSA_verify(
           issuer_key,
           signature,
           Poseidon(dob, credential_uid)
         ) = 1
         issuer_key_hash = Poseidon(issuer_ax, issuer_ay)
         dob <= ref_date - 180000
         nullifier = Poseidon(credential_uid, app_id)

    Boundaries

    • Issuer. The demo issuer key is generated by issuer/init.js. The verifier pins its Poseidon hash in config/issuer.json.
    • Signature. The circuit verifies EdDSA-Poseidon on BabyJubjub. RSA-2048 verification is not part of this build.
    • Setup. The Groth16 key came from a single-party powers-of-tau ceremony. It is not a production ceremony.
    • Nullifier. The identifier is unique per credential and application, not per person. A reissued credential gets a new nullifier.
    • State. Challenges are stateless HMAC tokens. Nullifiers live in Redis when configured, otherwise in process memory.

    Request path

    1. GET /api/challenge returns a signed token with a nonce, application id, and reference date.
    2. The browser builds the witness from a local credential and calls snarkjs.groth16.fullProve.
    3. POST /api/verify checks the token, public signals, trusted issuer hash, and Groth16 proof, then records the nullifier.
