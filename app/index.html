    Protocol
    
            
    What the KYC proof proves
    
            
    
              The relation binds an issuer’s KYC-complete claim, an expiry date, and an age rule.
              The included issuer is synthetic, not a real KYC provider.
            
    
          
    
        
    

        
    
          
    
            
    
              
    Relation
    
            
    
            
    public   ref_date, app_id, nonce, issuer_key_hash
private  dob, credential_uid, kyc_verified, expires_at,
         issuer_ax, issuer_ay,
         signature_r8x, signature_r8y, signature_s

prove    EdDSA_verify(
           issuer_key,
           signature,
           Poseidon(dob, credential_uid, kyc_verified, expires_at)
         ) = 1
         issuer_key_hash = Poseidon(issuer_ax, issuer_ay)
         kyc_verified = 1
         expires_at >= ref_date
         dob <= ref_date - 180000
         nullifier = Poseidon(credential_uid, app_id)
    
          
    

          
    
            
    
              
    Boundaries
    
            
    
            
      
              
    • 
                Issuer trust. The demo key is generated by
                issuer/init.js. The verifier can read its Poseidon hash from the
                configured EVM registry; otherwise it uses the local demo config.
              
      • 
              
    • 
                Signature. The circuit verifies EdDSA-Poseidon on BabyJubjub.
                RSA-2048 verification is not part of this build.
              
      • 
              
    • 
                Setup. The Groth16 key came from a single-party powers-of-tau
                ceremony. It is not a production ceremony.
              
      • 
              
    • 
                Nullifier. The identifier is unique per credential and application,
                not per person. A reissued credential gets a new nullifier.
              
      • 
              
    • 
                State. Challenges are HMAC tokens. Production requires shared Redis
                for replay and duplicate protection; local development uses process memory.
              
      • 
              
    • 
                India pilot boundary. A KYC and 18+ proof is not parental consent,
                a completed vKYC interaction, or a DPDP compliance certificate.
              
      • 
            
    
          
    
        
    

        
    
          
    
            
    Request path
    
          
    
          
    
            
            
      
              
    1. 
                GET /api/challenge returns a signed token with a nonce, application id,
                and reference date.
              
      2. 
              
    2. 
                The browser builds the witness from a local credential and calls
                snarkjs.groth16.fullProve in a background worker.
              
      3. 
              
    3. 
                POST /api/verify checks the token, public signals, trusted issuer hash,
                and Groth16 proof, then records the nullifier.
